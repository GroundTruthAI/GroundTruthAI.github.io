Featured industrial scenario

Train one predictive-maintenance model across 20 facilities without centralizing raw OT data

Illustrative enterprise scenario Assumptions for discussion, not contractual; results depend on workload-specific validation.

A manufacturer wants centralized predictive-maintenance training on data from all 20 of its facilities, while each facility keeps its original OT data in its authorized environment.

Each facility distills a task-specific dataset on site. After evaluation and owner approval, only that dataset crosses the existing DMZ.

Technology

How it works

Dataset distillation, not data compression

Compression shrinks the same data, which has to be decompressed before it is used, so AI training still processes all of it. Dataset distillation builds a much smaller training dataset for a specific task, which models use directly. How the two differ

  1. 1Reference architecture

    Access authorized source datasets

    Read-only access, granted by the data owner, inside the source environment.

  2. 2Experimental

    Generate a task-specific optimized dataset

    The runtime builds a compact training dataset for a defined model and task.

  3. 3Experimental

    Evaluate downstream predictive performance

    The same model is trained on full and optimized data and compared on the same test data.

  4. 4Reference architecture

    Transfer approved datasets where required

    Through the DMZ, gateway or pipeline you already control.

  5. 5Customer system

    Train centrally or run the validated workload

    On your existing ML and analytics platforms.

Experimental: implemented in the prototype used in internal experiments. Reference architecture: the deployment pattern a pilot implements with your teams. Customer system: your existing platforms. How dataset distillation works
